# scale-ops

클러스터의 노드 스펙과 트래픽 상황에 맞춰 애플리케이션의 **Resource** 및 **HPA(Horizontal Pod Autoscaler)** 설정을 자동으로 변경하는 GitLab CI 기반 자동화 레포지토리입니다.

GitOps 파이프라인을 통해 변경된 설정 파일이 커밋되며, ArgoCD가 이를 감지하여 클러스터에 즉시 반영합니다.

---

## 작동 방식 (Workflow)

1. 파이프라인 실행 시 특정 **`LEVEL`**을 변수로 지정합니다.
2. 스크립트가 `apps_list.txt`에 명시된 대상 애플리케이션 목록을 읽어옵니다.
3. 각 애플리케이션의 Git 프로젝트 내에 사전 정의된 `scaling-stage[LEVEL].yaml` 파일의 내용을 `values-scaling-active.yaml`로 복사(덮어쓰기)하고 커밋합니다.
4. **ArgoCD**가 `values-scaling-active.yaml` 파일의 변경을 감지하고 해당 스펙으로 자동 배포합니다.

---

## 스케일링 레벨 (LEVEL) 가이드

클러스터 노드 수와 트래픽 상황에 따라 5가지 레벨을 지원합니다.

| LEVEL | 노드 수 | 목적 및 설명 |
| :---: | :---: | :--- |
| **1** | 3개 | **기본 운영 상태** |
| **2** | 5개 | **확장 운영 상태** (트래픽 증가 대비) |
| **3** | 10개 | **핵심 서비스 A** 집중 사용/이벤트 기간 |
| **4** | 10개 | **타 핵심 서비스 B** 집중 사용/이벤트 기간 |
| **5** | - | **서비스 정지** (해당 앱들의 Pod Replicas를 `0`으로 설정) |

---

## 주요 기능 (Features)

* **안전한 테스트 (DRY_RUN)**
  * 파이프라인 환경 변수로 `DRY_RUN=true`를 설정하면, 실제 Git Push를 수행하지 않고 **예상되는 변경 결과만 로그로 확인**할 수 있습니다. 
  * 설정이 클러스터에 잘못 반영되는 것을 방지하기 위해 실제 배포 전 `DRY_RUN`을 활용하는 것을 권장합니다.

---

## 사용 방법 (How to Run)

GitLab Web UI를 통해 간편하게 HPA 및 리소스 설정을 변경할 수 있습니다.

1. 좌측 메뉴에서 **Build** > **Pipelines** 로 이동합니다.
2. 우측 상단의 **[New Pipeline]** 버튼을 클릭합니다.
3. **Run for branch name or tag** 에 실행할 브랜치를 선택합니다.
4. **Variables** 항목에 다음 변수를 입력합니다:
   * `LEVEL`: 변경하고자 하는 타겟 레벨 입력 (예: `1`, `2`, `3`, `4`, `5`)
   * `DRY_RUN`: 테스트 시 `true`, 실제 적용 시 `false` (또는 생략)
5. **[Run pipeline]** 버튼을 클릭하여 파이프라인을 실행합니다.

---

## 관련 파일

* `.gitlab-ci.yml`: HPA 및 Resource 자동 갱신을 수행하는 핵심 파이프라인 스크립트
* `apps_list.txt`: 스케일링 변경이 적용될 타겟 애플리케이션 리스트 파일
